# cases/ —— 语言无关的契约数据

这个目录放**不属于任何一种语言**的契约数据：字段名与形状、动作行为、cron 语义、
模板求值、分享令牌的字节。它入库，因为它是 Rust 侧那些契约测试的**输入**。

## ⚠️★ 这些是**冻结的输入**，本仓库是它们**唯一的主人**

它们原先由**前身实现（Go 版）导出**（生成器在 `cloud-clip/lib/*_fixture_test.go`），
拆库时被一起带了过来。**2026-10-10 起前身实现停止维护**，于是：

- **没有上游可同步了。** 以前那句「漂了是信号，说明 Go 侧的契约变了、Rust 该跟」
  **作废** —— 现在不存在「两边」。
- 它们从「别人导出的期望值」变成 **本仓库自己的冻结回归基准**。这反而更稳：
  不会再有人在上游改了结构体、让这边的测试莫名其妙地红。
- 所以下面这些**只读**规矩的**理由变了，但结论没变**：仍然不要随手改。
  区别在于现在**能改**了 —— 改它就是一次**契约变更**，走下面那条流程。

### 改这里的 JSON 是**契约变更**，按契约变更办

1. 先问：**这是不是线上形状？**（会不会让已有客户端拿到不同的东西）
2. 是 → 写清楚改什么、谁要跟着改、旧客户端会怎样，**单独一个提交**。
3. 改完必须让对应的契约测试**逐条重跑通过** —— 它不是「让测试变绿」，
   而是「把新的期望值钉住」。测试是这套东西唯一的牙，绕过它等于没有契约。

⚠️ 具体到 `actions/cases.json`：那里的期望值是**行为基准**。手改一条期望值
等于把「实现错了」改写成「基准错了」—— 这是这套东西最容易被滥用的地方，
所以那一条必须配一句**为什么新值才是对的**。

⚠️ 重算派生值（不是手改）只有一处，见下面 `share/`。

## protocol/ —— 线上 JSON 的形状

**是什么**：用 `encoding/json` 直接序列化真实结构体得到的字节，**不是手抄的**。

**谁消费**：`rust/crates/protocol/tests/contract_fixtures.rs` ——
读进来 → 反序列化 → 再序列化 → 与原文件深比较。

**为什么值得**：字段名与 `omitempty` 的**实际效果**只有真跑一遍序列化才说得准。
「读代码觉得一致」和「真的一致」是两件事。

⚠️ 比的是 JSON **语义**（`serde_json::Value` 深比较），不是字节。两处刻意的字节差异：
导出时开了 HTML 转义（`<` → `\u003c`），serde_json 不转义；以及 key 顺序。
两者都不是契约 —— 任何 JSON 解析器读出来都一样。

## share/ —— 分享令牌的字节

**是什么**：固定的配置 + 固定的 claims → 固定的 `keyHex` / `token`。

**谁生成**：拆库后**由本仓库自己重算** —— `rust/crates/core/tests/share_tokens.rs` 带
`UPDATE_FIXTURES=1` 时会把 `keyHex` 与 `token` 两个派生值重算写回，输入一个字不动。
（这是全目录**唯一**允许「重新生成」的地方，理由见下。）

**谁消费**：同一个文件 —— 逐字节复现密钥与 token，并把 token 解析回同一份 claims。

**为什么值得**：分享令牌的形状（`base64url(json).base64url(hmac)`）、claims 的
`omitempty` 效果、**密钥派生时房间的升序** —— 这三样读代码都看不出来，
而任何一处对不上都会导致**已发出的分享链接全变废链**，而且要等用户点开旧链接才发现。

⚠️ 换密钥标签那次（`cloud-clipboard-share-v1` → `clip9-share-v1`）就是用它重算的，而且
**先做了对照**：把标签临时改回旧值跑一遍重算，产物与当时那份夹具**逐字节相同** ——
证明这条重算路径和原来导出它的那套实现等价，然后才敢换标签重算。
**这条「先对照再换」的做法要留着**：它是唯一能证明重算路径没走偏的手段。

⚠️ 改它之前先读 `rust/crates/core/src/share.rs` 的模块注释：**红了意味着所有已发出的分享链接会失效**。

## actions/ —— 动作库的跨语言用例（190 条 / 34 个动作）

**是什么**：**注册表**与**每个动作的实际输出**。期望值是**跑出来的**、不是人写的 ——
生成器第一次跑就抓出了三条人写错的期望值。

**谁消费**：`rust/crates/actions/tests/contract_cases.rs` —— 逐条比对 + 逐字段对账元数据 +
单独钉住**刻意的差异**（大小写映射、URL 里的 `\s`、时分秒越界）。

**为什么值得**：动作库的边界全是「读代码看不出来」的那类 —— emoji 要走 **UTF-16 代理对**、
全角空格是 **U+3000**（不是 0x20+0xFEE0，那是未分配字符）、`[0-9]+` 是**贪婪**的、
base64 **不看**尾比特、`indent` 风格的美化**保键序**。
⚠️ 而且**同一串正则在三个引擎里语义不同**（`\d` / `\b` / `\s`）——
「这边是 Unicode、JS 是 ASCII」读代码永远看不出来，只能拿用例钉。

⚠️ 这套用例同时是**动作注册表**的契约：`id` / `group` / `key` / 参数声明逐字段钉死。
加一个动作**必须**同时进 `registry.json` 与 `cases.json`，否则
`contract_cases.rs` 的「实现 ∪ 未实现 == 注册表」那条会红。

## cron/ · render/ · task/ —— 语义边界

- `cron/cron.json`：52 解析 + 44 描述 + 35 求时刻。日/周是 **OR**、`?` 等价 `*`、
  **7 也是周日**、`a/n` 按 `a-max` 理解、跨月跳步的近似、闰日要等两年、
  以及「语法合法但永远等不到」靠**迭代上限**兜底。
- `render/render.json`：38 条。偏移**挂在变量自己身上**（`{{weekday:+1d}}`）、
  **月溢出夹取**（1 月 31 日 +1m 要夹到 2 月底）、周几四种写法（`en` 是**全名**）、
  求值**要么全成功要么整体失败**。⚠️ `{{uuid}}` / `{{timestamp}}` 是**不确定**的，
  fixture 用 `uncertain` 标注、不记字面值。
- `task/task.json`：10 求值 + 12 校验（四档频次的归一化、判到期用 `prev`）。
